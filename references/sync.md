# 从候选书到微信读书书单

## 准备本批次

以下命令中的脚本路径以已安装的组合技能为基准。使用当前工作区保存批次，正常运行无需用户提供 JSON。先检查同一聊天是否有未完成的批次。预览任务可直接展示两份草案，不操作账号。每本在推荐结果中写出“为什么现在读”、实际讨论时间和原始链接；个性化候选另附笔记依据，开放榜注明讨论平台。

在批次目录准备 UTF-8 的 `draft.json`。以下仅展示结构，占位符全部用实际材料替换。

```json
{
  "as_of": "YYYY-MM-DD",
  "personal": [{
    "bookId": "<电子书 ID>", "title": "<平台书名>", "author": "<平台作者>",
    "reason": "<本书哪一部分回应了笔记中的哪个问题>",
    "note": {"path": "<笔记相对路径.md>", "heading": "<真实小节标题，省略井号>"},
    "evidence": [{"date": "YYYY-MM-DD", "voice": "<平台、读者或节目>", "url": "<这次讨论的原文>"}]
  }],
  "open": [{
    "bookId": "<电子书 ID>", "title": "<平台书名>", "author": "<平台作者>",
    "reason": "<读者具体在讨论什么，以及为什么值得读原书>",
    "evidence": [{"date": "YYYY-MM-DD", "voice": "<平台、读者或节目>", "url": "<这次讨论的原文>"}]
  }]
}
```

在本批次目录运行。PowerShell 示例中的脚本路径可随安装目录调整。

```powershell
$books = Join-Path $env:USERPROFILE '.codex/skills/last30days-weread/scripts/booklists.py'
python -X utf8 $books prepare draft.json --vault <笔记目录> --state plan.json
python -X utf8 $books status plan.json
```

将命令中的 `<笔记目录>` 替换为实际路径。已设置 `WEREAD_VAULT` 时可省略该参数。笔记没有小标题时可省略输入的 `heading`。计划绑定当前微信读书账号，保留两榜的来源、版本和批次号。已经存在的计划用 `status` 继续。

## 在官方界面写入

由 Codex 操作可交互的浏览器或原生客户端。若已安装的微信读书助手后续新增书单写入功能，从其文档与官方 `/_list` 核实权限、对象和回读方式后也可使用。现有的 `/page/submit` 提交阅读报告，`/shelf/sync` 回读书架。两者都不能创建个人书单。

1. **定位自己的账号。** 打开已登录的微信读书官方页面或客户端，在个人页核对与 `status` 返回的账号一致。登录页过期时刷新二维码并交给用户扫码，保留批次。若网页版只有书架，从可操作的微信读书客户端的“我”或书架菜单寻找“书单 / 我的书单 / 我创建的”。按实际可见按钮操作；将“收藏的书单”与自己创建的书单区分开。
2. **按缺项入架。** 对 `shelf_missing` 中每个版本打开计划中的官方阅读链接，核对书名和作者，点击“加入书架”。若已显示“已在书架”，跳过。再运行一次 `status`。状态未刷新时重新打开书架观察，避免连续点同一开关。遇付费提示时只执行入架，购买需要用户另外授权。
3. **定位两个书单。** 在自己创建的书单内按精确名称查找，展开“更多”并翻完可见分页。同名且能编辑的条目唯一时打开，记下界面实际给出的书单链接或标识，后续优先按它定位；同名多份先按本批次已记录的标识匹配。仍有歧义时只暂停有歧义的那份，另一份继续。确认遍历完仍无匹配才点击“新建书单 / 创建书单”，照抄计划名称。有仅自己可见选项时选它；“开放”仅表示选书来源。现有书单用原有的可见性。若新建只能公开发布，先保存草稿，等用户决定是否公开。
4. **添书并保存。** 在书单编辑页点“添加书籍”，优先从书架的同版条目勾选所有缺项，再点“完成 / 保存”。如果当前界面从书籍详情提供“添加到书单”，也可逐本打开已核对的版本，选择目标书单，并确认。新建表单必须先选书才能保存时，在同一个表单完成以上步骤。保留已有条目；同一本入选两榜时只在书架添加一次，两张书单各勾选一次。中断、卡顿或保存超时时重新打开目标书单查成员，再补缺。若客户端只提供书架分组，保留计划并说明还缺可操作的个人书单入口。
5. **重新打开验收。** 离开编辑页，再分别从“我创建的”重新打开两份书单。以每本可见的官方阅读链接对应计划版本。界面不显示链接时打开书籍详情，比对完整书名、作者和需要时的译者、出版社等以唯一识别版本。辨认不出的条目不计入已核验。只在当前账号和真实书单中有此证据时填写下节的观察。不要从计划复制成员冒充回读。

## 回读和续办

由 Codex 把刚才实际看到的结果写为批次目录的 `observed.json`。写入修改后，原观察立即失效。再次观察再覆盖。示意结构如下。

```json
{
  "run": "<plan.json 中的 run>",
  "account_checked": true,
  "observed_at": "<实际观察时间，ISO 8601 含时区>",
  "lists": {
    "last30days个性化书单": {"state": "present", "scope": "my_created_booklists", "all_pages": true, "members": ["<实际看到的版本 ID>"]},
    "last30days开放书单": {"state": "unknown", "all_pages": false, "members": []}
  }
}
```

`present` 表示已进入所有者自己的这份书单。此时 `all_pages` 指书目已读到末尾。`missing` 只在对“我创建的”完整查找后使用，此时 `all_pages` 指所有书单均已查过。`ambiguous` 表示同名且未定位。以上三种观察填写 `scope: my_created_booklists`。尚未看见自己的书单入口填 `unknown`。可在观察中用可选的 `list_link` 或 `list_id` 保存实际定位信息。扫码后或更换界面再核对一次账号与书单。

```powershell
python -X utf8 $books status plan.json --ui observed.json
```

按返回动作执行：`inspect` 继续查界面；`identify_list` 定位同名书单；`create` 创建；`add_missing` 仅添加 `outstanding_ids`；`verified` 表示该书单的目标版本已全部看到。若同一份书单在新建与保存之间发生变化，采用重新打开后看到的状态。仅在总结果 `verified=true` 时报告两份书单及书架均已同步。部分成功就分别列出每榜的已核验数、目标数和具体待办；附上真实书单链接（若有）。只有调用者还需手动登录或决定公开时才请求其操作。
